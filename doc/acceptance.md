## 1. Схема развёртывания стенда

Развёртывание выполнено в изолированном Docker Compose окружении с маршрутизацией через обратный прокси Caddy:

```text
Интернет (HTTPS/HTTP)
       │
       ▼  Порты :443 / :80
┌────────────────────────────────────────────────────────┐
│ pi5server (Host)                                       │
│                                                        │
│  ┌────────────────────────┐                            │
│  │ caddy-proxy (Caddy 2)  │ (авто-TLS Let's Encrypt)   │
│  └───────────┬────────────┘                            │
│              │ Сеть: caddy-public                      │
│              ▼                                         │
│  ┌────────────────────────┐                            │
│  │ abs_web (Nginx)        │ :8080 host / :80 internal  │
│  │ - Статика UI (/)       │                            │
│  │ - Proxy /api/, /docs   │                            │
│  └───────────┬────────────┘                            │
│              │ Сеть: abs-inventory_default             │
│              ▼                                         │
│  ┌────────────────────────┐    ┌────────────────────┐  │
│  │ abs_app (FastAPI)      │───▶│ abs_db (Postgres)  │  │
│  │ :8000                  │    │ :5432              │  │
│  └────────────────────────┘    └────────────────────┘  │
└────────────────────────────────────────────────────────┘
```

Конфигурация `docker-compose.prod.yml` связывает сервис `abs_web` с внешней сетью `caddy-public`, сохраняя независимость базового файла `docker-compose.yml` для локальной разработки.

### 2.3. Бизнес-контракты и аналитические API

Проверены основные функциональные модули backend через публичный домен:

1. **Складской учёт (`/api/stock`, `/api/movements`)**:
   - `GET /api/stock?as_of=2026-09-29`: возвращает актуальные остатки по складам и партиям. Остаток `DEMO-OIL` на `DEMO-MS-01` равен 50.000 шт.
   - `GET /api/stock/DEMO-EXPIRED?as_of=2026-09-29`: корректно разделяет общий остаток (10.000 шт.) и доступный (0.000 шт.) с учётом истекшего срока годности.
   - `GET /api/movements`: постраничная пагинация (limit/offset) и фильтрация по дате работают штатно.
2. **Прогнозирование расхода (`/api/forecast`)**:
   - `POST /api/forecast` (`DEMO-OIL`, горизонт 3 мес.): возвращает рекомендацию 45.000 шт. на сумму 4500.00 руб., содержит детализированное математическое обоснование расчёта.
3. **Предупреждения о рисках (`/api/alerts`)**:
   - `GET /api/alerts?sku=DEMO-DEFICIT&location=DEMO-MS-02`: критическое предупреждение о дефиците (`stockout`, уровень `critical`) формируется корректно.
4. **План закупок и бюджет (`/api/procurement/plan`)**:
   - `POST /api/procurement/plan` (`horizon_months: 1`): возвращает сводную потребность с детализацией по месяцам, SKU, категориям и складам. Известная сумма закупки `2900.00` руб.

### 2.4. Веб-интерфейс и пользовательский сценарий

- Доставка статических ресурсов (`/`, `/styles.css`, `/js/*.js`) выполняется веб-сервером Nginx с кодами 200.
- Все ключевые экраны («Склад», «Риски и прогноз», «План закупок и бюджет», «Проверка ТЗ») функциональны и заполняются актуальными данными из API.
- Интерактивный проверочный стенд API позволяет тестировать обязательные методы без ручного ввода параметров.

### 2.5. Воспроизводимость данных и сброс

- При старте продуктового контейнера автоматически накатываются миграции Alembic (`initial_domain_schema`, `backfill_movement_versions`) и выполняется начальное сидирование.
- Вызов сброса данных (`python -m app.demo_data.reset && python -m app.demo_data.bootstrap`) восстанавливает эталонный набор на контрольную дату `2026-09-29`:
  - Объектов: 2
  - Поставщиков: 2
  - Товаров: 9
  - Закупочных условий: 8
  - Складских движений: 105
  - Партий: 9

### 2.6. Эксплуатационное журналирование

- Журналы сервисов `abs_db`, `abs_app`, `abs_web` доступны через команду `docker compose logs`.
- Логирование входящих HTTP-запросов и ответов функционирует штатно, фатальные ошибки и необработанные исключения отсутствуют.
