# Демонстрация веб-интерфейса

## Запуск

Из корня проекта, при установленном Docker с Compose:

```bash
docker compose up --build
```

Дождитесь готовности `app` и запуска `web`, затем откройте `http://localhost:8080/`. Если в `.env` задан `WEB_PORT`, используйте `http://localhost:<WEB_PORT>/` (порт по умолчанию — `${WEB_PORT:-8080}`). Каждый запуск контейнера `app` после миграций очищает предметные таблицы и заново загружает сиды и демонабор. Отдельная команда подготовки данных не нужна. Для обычной остановки нажмите Ctrl+C; `docker compose down` сохраняет том БД, но следующий запуск `app` сбросит проведённые операции.

Дата в шапке «Дата снимка» приходит из `/api/demo/status` и при каждом запуске `app` устанавливается на текущую дату Москвы. Контрольные числа ниже относятся к чистому набору на `2026-09-29`; при другой дате даты документов сдвигаются. Во время работы стенда движения по любым SKU, включая `DEMO-`, меняют реальные остатки и расчёты. Следующий запуск приложения восстановит исходные значения и удалит записи посетителей.

## Маршрут показа

Под компактной шапкой расположены два крупных блока выбора: «Проверка эндпоинтов» и «От склада к бюджету». На первом экране карточки изначально свёрнуты. Раскройте любую карточку: до запуска виден подготовленный запрос с редактируемыми полями. После нажатия «Запустить проверку» под ним появляются фактически отправленный запрос, ответ и результат; «Полный JSON ответа» раскрывается нажатием или клавиатурой. Изменение входных данных может привести к расхождению с готовым контрольным примером. Второй экран содержит сквозной маршрут и заглушку AI-помощника в конце.

1. Запустите читающие карточки «Остаток», «Партии и просрочка», «Журнал», «Прогноз», «Риск дефицита» и «Нет движения». Для журнала нажмите «Следующая страница»: отправляется тот же фильтр со смещением `offset=2`. В запросе предупреждения поле «Тип» выбирается из допустимых значений; дата, горизонт и числовые поля используют соответствующие элементы ввода. Чистый снимок `2026-09-29` даёт `50.000` масла, `10.000`/`0.000` для просроченного товара, рекомендацию `45.000` на `4500.00 ₽`, уровни `critical` и `info` для двух рисков. После операций посетителей фактические числа могут измениться.
2. Запустите «Приход», затем «Расход FEFO». Все подготовленные шаги видны до запуска; зависимый запрос выполняется после успешной записи. Сайт создаёт новые `CHECK-*` документы для `OIL-001`/`MS-01`, показывает `201`, ID и фактический остаток, проверяет партию отдельным запросом и связывает `allocations[].batch_id` со сроком партии. Для повторения записи нажмите «Подготовить новый запрос», затем «Запустить проверку»: номер документа обновится. На общем стенде остаток меняется после каждого запуска: значения `18.000` и `17.000` верны лишь для чистой БД после одной пары операций.
3. Запустите «Неизвестный SKU», «Неизвестный объект», «Нулевой расход», «Нулевой приход», «Избыточный расход», «Будущая дата» и «Повтор документа». Карточки показывают ожидаемые `404`, `422` и `409` с русским сообщением и кодом ошибки. «Повтор документа» сначала показывает успешный `201`, затем отправляет тот же JSON и показывает `409`; отказ не обозначается проведённым движением.

После этого переключитесь в «Сквозной маршрут» для склада, рисков, прогноза, плана, бюджета и ручной формы движения.

1. **Склад.** В таблице «Остатки по товарам и объектам» найдите `DEMO-OIL` на `DEMO-MS-01`. Учётный и доступный остатки на чистом снимке — `50.000`. Нажмите строку: раздел «Партии» показывает сроки, цены и документы прихода. Для `DEMO-EXPIRED` на `DEMO-MS-01` учётный остаток — `10.000`, доступный — `0.000`. В «Журнале движений» задайте SKU, нажмите «Применить фильтры», откройте следующую страницу кнопкой «Далее →» и проверьте распределения расхода по партиям и отметку FEFO.
2. **Риски.** Перейдите по «Риски и прогноз» к таблице «Предупреждения». Найдите дефицит `DEMO-DEFICIT` и риск срока годности `DEMO-EXPIRY`; раскройте «Исходные показатели» у предупреждения.
3. **Прогноз.** В том же разделе просмотрите «Прогноз выбранной пары» для `DEMO-OIL` и `DEMO-MS-01`. Пара меняется выбором строки склада. Проверьте остаток, средний расход, поставки в пути, страховой запас, точку заказа, рекомендуемое количество, стоимость и даты. Раскройте объяснение с исходными данными, формулами, допущениями и дневным прогнозом.
4. **План закупок.** Перейдите в «План и бюджет». По умолчанию выбран горизонт «3 месяца»; на чистом снимке `2026-09-29` позиция `DEMO-OIL`/`DEMO-MS-01` содержит `30.000` и `3000.00 ₽`. Смените горизонт на «1 месяц»: расчёт запустится сразу. Измените объект, категорию, страховой запас или лимит и нажмите «Пересчитать»; проверьте применённые параметры, период, позиции и существующие заказы.
5. **Бюджет.** В результате того же плана просмотрите известную часть суммы и разрезы по месяцам, товарам, категориям и объектам. Если цена или стоимость позиции неизвестна, интерфейс показывает «Нет данных» и признак неполного бюджета: известная сумма не является полной стоимостью. Недатированные позиции показаны отдельно; их нельзя считать заказами с известной датой. Проверьте статус лимита, предупреждения и объяснение расчёта.
6. **Движение `OIL-001`.** Перейдите в «Операция» → «Провести движение». Для предзаполненных `OIL-001`/`MS-01` выберите «Приход»: укажите дату операции, `2.000`, новый уникальный номер документа, номер партии и цену `100.00 ₽`; срок годности можно оставить пустым. Нажмите «Провести движение». В результате должны появиться ID, учётный и доступный остатки; склад и журнал обновляются. Затем выберите «Расход», укажите `1.000` и другой новый номер документа. Результат показывает распределения по партиям, а остаток уменьшается на `1.000`.

## Ручная проверка в браузере

- Раскройте и сверните любую карточку; в свёрнутом виде остаются название, маршрут и статус. До запуска измените одно поле запроса и проверьте новый фактический URL или тело, затем раскройте JSON, проверьте вторую страницу журнала, статусы `200`/`201`/`404`/`409`/`422`. Для повтора «Прихода» подготовьте новый запрос: номера документов должны различаться, остаток должен браться из нового ответа. Во время выполнения поля и кнопка заблокированы. При недоступном API карточка показывает «Ответ не получен», без ложного результата.
- Обновите страницу и убедитесь, что дата снимка и данные загружаются без входа; ссылки навигации ведут к нужным разделам. Блок «AI-помощник — в разработке» не содержит работающего чата.
- Проверьте фильтр и вторую страницу журнала, раскрытие показателей риска и формул прогноза, пересчёт `3 → 1` месяц, неизвестную цену и позицию без даты заказа. После пересчёта старый ответ не должен заменять новый.
- В форме можно выбрать `DEMO-OIL` и провести приход с новым номером документа: остаток и журнал должны обновиться. Затем проведите приход и расход `OIL-001` из маршрута выше. Повторите номер уже проведённого документа: форма должна показать ошибку `HTTP 409`, а не сообщение об успешной операции. Перезапуск `app` вернёт исходные остатки.
- Если раздел сообщает об ошибке загрузки, используйте расположенную рядом кнопку «Повторить». Страница API доступна по ссылке «API» (`/docs`).

Для повторения исходных контрольных чисел перезапустите `app`: это удалит все операции, проведённые после предыдущего запуска, включая записи для обычных и `DEMO-` SKU.
