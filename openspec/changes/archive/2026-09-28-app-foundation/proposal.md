# Основа приложения

## Why

После согласования предметной модели на этапе 04 нужен запускаемый каркас, на котором можно проверяемо реализовать складские операции и расчёты. Этап 05 должен дать воспроизводимый запуск сервиса и PostgreSQL, схему БД и минимальные стартовые данные без преждевременной реализации бизнес-операций.

## What Changes

- Создать модульный каркас FastAPI с конфигурацией из окружения, подключением к PostgreSQL и минимальной проверкой готовности сервиса.
- Создать первую миграцию Alembic для всей согласованной предметной модели, включая таблицу блокировки пары «товар + объект» и ограничения целостности.
- Сначала настроить Docker Compose как среду разработки и сдачи; обеспечить запуск сервиса, PostgreSQL, миграций и идемпотентной загрузки начальных справочников и закупочных условий одной командой.
- Устанавливать зависимости в образ через `pip` и `requirements.txt`; запускать Ruff и pytest в контейнере, предоставить `.env.example` и краткую инструкцию запуска в дизайне изменения.
- Проверить миграции, повторный запуск сидов и минимальные интеграционные сценарии без HTTP-операций склада.

## Capabilities

### New Capabilities

- `app-foundation`: воспроизводимый запуск, конфигурация, готовность сервиса, миграции и начальные данные этапа 05.

### Modified Capabilities

Нет. Существующие спецификации предметных возможностей не меняются; новая схема подготавливает их последующую реализацию.

## Impact

Появятся код приложения, модели SQLAlchemy, миграция Alembic, конфигурация, тестовая инфраструктура, Dockerfile, `docker-compose.yml` и `.env.example`. Краткие проверенные команды запуска останутся в дизайне изменения; полный README подготавливается на заключительном этапе ROADMAP. Эндпоинты движений, остатков, прогноза, предупреждений и закупок относятся к следующим этапам. Партии и движения в стартовых данных появятся на этапе 06 через складские правила; требование итогового ТЗ о проверяемом API со стартовыми данными будет выполнено после него.
