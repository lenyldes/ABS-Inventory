# Spec Delta: deployment

## Purpose

Обеспечивает продуктовое развёртывание демонстрационного стенда ABS Inventory в контейнеризированном окружении на сервере, интеграцию с внешним обратным прокси Caddy через сеть caddy-public, безопасный доступ по HTTPS на домене abs-inventory.lenyldes.ru и проверяемость приёмочных критериев системы.

## ADDED Requirements

### Requirement: Продуктовая конфигурация Compose и изоляция сетей
Система ДОЛЖНА (SHALL) предоставлять отдельную конфигурацию `docker-compose.prod.yml`, подключающую веб-сервис `abs_web` к внешней Docker-сети `caddy-public`, не нарушая при этом автономность локальных тестов и базового `docker-compose.yml`.

#### Scenario: Автономность локальных проверок
- **WHEN** запускается локальный сценарий `bash scripts/check.sh` в окружении без сети `caddy-public`
- **THEN** все проверки и жизненный цикл Compose выполняются успешно через базовый `docker-compose.yml`.

#### Scenario: Подключение к внешней сети Caddy на сервере
- **WHEN** стек запускается с объединением конфигураций `-f docker-compose.yml -f docker-compose.prod.yml`
- **THEN** контейнер `abs_web` входит как во внутреннюю сеть проекта, так и во внешнюю сеть `caddy-public`.

### Requirement: Маршрутизация и HTTPS через Caddy
Обратный прокси Caddy на сервере ДОЛЖЕН (SHALL) перенаправлять входящий HTTPS-трафик с домена `abs-inventory.lenyldes.ru` на порт 80 контейнера `abs_web` с автоматическим выпуском TLS-сертификата и редиректом с HTTP на HTTPS.

#### Scenario: Безопасный доступ и редирект
- **WHEN** отправляется HTTP-запрос на `http://abs-inventory.lenyldes.ru`
- **THEN** выполняется редирект на `https://abs-inventory.lenyldes.ru` с валидным TLS-сертификатом и отдаётся веб-интерфейс.

#### Scenario: Проксирование статики и API
- **WHEN** выполняется запрос к `https://abs-inventory.lenyldes.ru/health` или `https://abs-inventory.lenyldes.ru/api/warehouse/inventory`
- **THEN** запрос успешно маршрутизируется через Caddy в Nginx и далее в бэкенд, возвращая корректный JSON-ответ со статусом 200.

### Requirement: Автоматическая инициализация и восстановление данных
Развёрнутый стенд ДОЛЖЕН (SHALL) автоматически применять миграции базы данных и загружать эталонный демонстрационный набор при запуске, а также поддерживать онлайн-восстановление данных.

#### Scenario: Автоматическая инициализация при старте
- **WHEN** запускается продуктовый стек на сервере
- **THEN** миграции Alembic применяются, и демоданные на контрольную дату `2026-09-29` автоматически разворачиваются.

#### Scenario: Восстановление данных через веб-интерфейс
- **WHEN** пользователь инициирует сброс демоданных через интерфейс или API
- **THEN** база данных возвращается в исходное эталонное состояние с подтверждением статуса готовности.

### Requirement: Эксплуатационное журналирование и диагностика
Стенд ДОЛЖЕН (SHALL) сохранять журналы работы сервисов приложения, веб-сервера и базы данных, доступные для инспекции стандартными средствами Compose.

#### Scenario: Просмотр журналов сервисов
- **WHEN** запрашиваются журналы `docker compose logs` для сервисов `web`, `app` и `db`
- **THEN** вывод содержит информативные записи запуска и обработки запросов без фатальных необработанных сбоев.
