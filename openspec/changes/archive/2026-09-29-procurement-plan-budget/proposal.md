# Proposal

## Why

Сейчас API рассчитывает одну закупку для одного товара и объекта на весь горизонт. Управляющий не может получить согласованный план повторных закупок нескольких товаров и проверить, сколько дополнительных средств потребуется по месяцам, категориям и объектам.

## What Changes

- Добавить расчётный, не сохраняемый план дополнительных закупок на 1, 3, 6 или 12 месяцев от даты актуальности с месячным шагом пополнения.
- Считать позиции по парам «товар + объект», учитывая годность партий, расход, ожидаемые поставки, срок поставки, страховой запас, минимум и кратность заказа.
- Возвращать позиции с датами заказа и поступления, количеством, стоимостью, предупреждениями и объяснением; группировать один набор позиций по календарным месяцам заказа, товарам, категориям и объектам.
- Показывать известную сумму, неполноту бюджета из-за отсутствующих цены или срока поставки и сравнение с необязательным лимитом без автоматического изменения заказов.
- Оставить ранее оформленные заказы входом прогноза, а их стоимость — вне бюджета новых рекомендаций. Существующий контракт `/api/forecast` не менять.

## Capabilities

### New Capabilities

- `procurement-plan-budget`: расчёт повторных закупок, API плана и сверяемая детализация бюджета.

### Modified Capabilities

Нет: действующие правила `forecasting`, `forecasting-api` и `procurement` используются без изменения их контрактов.

## Impact

Новый API расчёта плана и модуль планирования используют данные каталога, складской истории, условий основного поставщика и ожидаемых заказов. Потребуются чистые расчётные функции, схемы ответа, выборка по объекту и категории, проверка арифметики бюджета и сценариев с неполными данными. Хранение плана, автоматическое создание заказов, календарные кварталы и управление существующими заказами в изменение не входят.
