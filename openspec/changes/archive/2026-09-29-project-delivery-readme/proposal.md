# Proposal: Итоговая передача проекта и формирование README

## Why

Проект подошёл к завершающему этапу 13 дорожной карты («Передача и защита результата»). Все функциональные и инфраструктурные требования тестового задания и согласованного расширения выполнены: реализованы складской учёт, FEFO, прогноз потребности, предупреждения о рисках, многопериодный план закупок и бюджет, синтетические данные, веб-интерфейс и проверен боевой стенд. Для финальной передачи проекта необходимо подготовить ёмкий, структурированный и презентабельный файл `README.md`, который продемонстрирует высокое качество реализации, инженерную культуру разработки в паре с ИИ (AI-assisted engineering), предоставит инструкции запуска и тестирования, детально раскроет архитектуру и формулу остатка, а также зафиксирует ответы автора по мотивации из ТЗ.

## What Changes

- Создание итогового файла `README.md` в корне проекта (в строгом соответствии с лимитом `<= 10 000` символов из `AGENTS.md`):
  - заголовок, краткое описание и ссылки на живой стенд, Swagger UI и OpenAPI-спецификацию;
  - демонстрационный стенд: ссылка `abs-inventory.lenyldes.ru`, интерактивный проверочный стенд API без ввода параметров, восстановление эталонных данных;
  - соответствие ТЗ: покрытие обязательных эндпоинтов, обработка краевых случаев, FEFO, детерминированные расчёты;
  - архитектура решения: модульный монолит, разделение слоёв (API, репозитории доступа к данным, чистые функции расчётов), точный алгоритм расчёта остатка из движений и партий без денормализованного поля;
  - стек технологий и обоснование архитектурных решений (FastAPI, PostgreSQL 18, SQLAlchemy 2.0, Alembic, Pydantic v2, Docker Compose, Caddy 2, pytest);
  - инструкции по запуску проекта и проверке через curl / Postman;
  - инструкции по запуску тестов и сценариев Zero-Defect (`pytest`, `bash scripts/check.sh`);
  - описание переменных окружения из `.env.example`;
  - описание инженерного процесса: разработка с ИИ по методологии OpenSpec, TDD, протокол Stop-and-Review, контроль лимитов;
  - блок мотивации автора: ответы на 3 вопроса из ТЗ (интерес к проекту, роль в команде, график и доступность).
- Актуализация `doc/ROADMAP.md` с отметкой о выполнении этапа 13 и общего завершения дорожной карты.

## Capabilities

### New Capabilities
- `delivery`: Требования к структуре, содержанию и критериям приемки итогового README проекта, описанию архитектуры, формулы остатка, технологического стека, инструкций запуска и тестирования, презентации демонстрационного стенда, блоку мотивации автора и закрытию дорожной карты.

### Modified Capabilities
*(Отсутствуют. Функциональные контракты API и предметная модель зафиксированы ранее).*

## Impact

- Заменяется заголовочный файл `README.md` в корне репозитория на полноценный итоговый документ.
- Обновляется файл `doc/ROADMAP.md` (критерии этапа 13 помечаются выполненными).
- Все обязательные проверки `bash scripts/check.sh` продолжают выполняться без сбоев.
