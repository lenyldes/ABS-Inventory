# Proposal

## Why

После этапа 06.1 ошибочное движение нельзя исправить или отменить через API, сохранив проверяемую историю. Для начала прогнозирования нужна актуальная исправленная история склада и согласованная с ней приёмка заказов.

## What Changes

- Добавить предварительный просмотр, атомарное подтверждение связанных исправлений и отмен, отказ при устаревшем просмотре и историю версий движения.
- Проверять исторические остатки по партиям, связанные возвраты, уникальность активных документов и влияние приёмки на ожидаемую поставку.
- Уточнить контракт изменения количества расхода: клиент явно задаёт новые количества затронутых строк распределения; автоматического перераспределения партий нет.
- Создавать начальную версию аудита для каждого нового движения и восстановить её для уже записанных движений.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `movement-amendments`: уточнить состав правки расхода, проверку связанных строк и наблюдаемую историю версий.

## Impact

Затрагиваются `POST /api/amendments/preview`, `POST /api/amendments/confirm`, `GET /api/movements/{id}/history`, создание движений, расчёт истории склада, данные аудита и связанных заказов поставщику. Используются существующие PostgreSQL, SQLAlchemy, FastAPI и таблицы исправлений; при необходимости схема расширяется новой миграцией Alembic.
