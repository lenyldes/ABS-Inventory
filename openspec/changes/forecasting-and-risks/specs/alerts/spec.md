# Spec Delta

## MODIFIED Requirements

### Requirement: Виды, горизонт и важность
GET `/api/alerts` SHALL вычислять предупреждения при запросе по актуальным данным на дату `as_of` (по умолчанию сегодняшняя дата в часовом поясе `Europe/Moscow`). Если `horizon_days` не задан, горизонт прогнозных предупреждений для товара SHALL составлять `max(30, lead_time_days + 1)` календарных дней; при неизвестном сроке поставки SHALL использоваться 30 дней с указанием ограничения расчёта. Если `horizon_days` задан, SHALL использоваться ровно указанное число дней для всех товаров запроса. Прогноз начинается с `as_of + 1` и заканчивается на `as_of + horizon_days` включительно. Применённые горизонт и конечная дата SHALL входить в `metrics` каждого предупреждения, зависящего от прогноза.

| Вид | Условие и горизонт проверки | Уровень |
|---|---|---|
| Дефицит | Оценивается на установленном горизонте прогноза: доступный запас равен 0 при $a > 0$, либо исчерпание происходит до возможного прибытия заказа ($t_{stockout} \le as\_of + L$) | `critical` |
| Потенциальный дефицит | Доступный остаток меньше точки заказа, но дата заказа ещё не просрочена ($t_{order} > as\_of$) | `warning` |
| Приближение срока | Положительный остаток годной партии, до истечения срока осталось $\le$ порогового числа дней (по умолчанию 30 дней) | `warning` |
| Просрочка | Положительный физический остаток на складе с датой годности $< as\_of$ | `critical` |
| Нет движения | На объекте есть остаток товара, но за пороговый период (по умолчанию 90 дней) не было ни одной операции расхода | `info` |
| Риск списания | Часть партии по FEFO-моделированию установленного горизонта прогноза не будет использована до истечения срока годности | `warning` |
| Неполная история | С момента первой активной операции товара на дату `as_of` прошло менее 90 дней либо активных операций на эту дату ещё нет; в последнем случае `history_days` равен 0, а `first_movement_date` — `null` | `info` |

Механизмы прочтения, скрытия и отправки уведомлений не входят в прототип.

#### Scenario: Просроченный остаток
- **WHEN** партия остаётся на складе после окончания срока годности
- **THEN** система показывает `critical` с её количеством, но не создаёт списание.

#### Scenario: Поставка после исчерпания
- **WHEN** положительное потребление исчерпает запас до даты поставки
- **THEN** система показывает риск дефицита, даже если сумма ожидаемых поставок покрывает весь горизонт.

#### Scenario: Задержанная поставка не маскирует дефицит
- **WHEN** поставка ожидалась до или в день `as_of`, но не принята, а запаса на складе нет
- **THEN** система формирует критический дефицит, не считая задержанную поставку доступным запасом.

#### Scenario: Срок поставки длиннее 30 дней
- **WHEN** срок поставки равен 45 дням и `horizon_days` не задан
- **THEN** прогнозные предупреждения проверяются на 46 дней и содержат этот горизонт и конечную дату в `metrics`.

#### Scenario: Явный горизонт
- **WHEN** передан `horizon_days=7` для товара со сроком поставки 45 дней
- **THEN** прогнозные предупреждения проверяются ровно на 7 дней и указывают этот горизонт в `metrics`.

#### Scenario: Заказ до первой приёмки
- **WHEN** для товара и объекта создан заказ поставщику, но на дату `as_of` нет активных складских операций
- **THEN** система показывает `incomplete_history` уровня `info` с `history_days=0` и `first_movement_date=null`.

### Requirement: Контракт GET `/api/alerts`
Система SHALL предоставлять эндпоинт фильтрации предупреждений:
- **Query-параметры**: `location` (str), `sku` (str), `type` (enum: `stockout`, `potential_stockout`, `expiring_soon`, `expired`, `no_movement`, `writeoff_risk`, `incomplete_history`), `level` (enum: `critical`, `warning`, `info`), `as_of` (date, def today), `horizon_days` (int $\ge 1$ | null), `shelf_life_days_threshold` (int, def 30, $\ge 1$), `no_movement_days_threshold` (int, def 90, $\ge 1$), `limit` (int, 1..100, def 50), `offset` (int, $\ge 0$, def 0).
- **Ответ 200 OK**:
  ```json
  {
    "items": [
      {
        "id": "alert-stockout-MSK-01-OIL-500-2026-09-28",
        "type": "stockout",
        "level": "critical",
        "sku": "OIL-500",
        "location": "MSK-01",
        "batch_id": null,
        "message": "Критический дефицит: исчерпание запаса до возможного прибытия заказа",
        "metrics": {
          "available_stock": "0.000",
          "average_daily_consumption": "1.500000",
          "lead_time_days": 5,
          "days_of_stock": "0.0",
          "horizon_days": 30,
          "horizon_end": "2026-10-28"
        },
        "as_of": "2026-09-28"
      }
    ],
    "total": 1,
    "limit": 50,
    "offset": 0
  }
  ```
- **Ошибки**: `400` (пороги $< 1$, `horizon_days < 1`, `limit` вне [1, 100], `offset < 0`), `422` (невалидный формат даты `as_of`).

#### Scenario: Фильтрация по уровню и объекту
- **WHEN** клиент запрашивает GET `/api/alerts?location=MSK-01&level=critical`
- **THEN** система возвращает только критические предупреждения по указанному филиалу с кодом `200`.

#### Scenario: Некорректный порог
- **WHEN** передан `shelf_life_days_threshold=0`
- **THEN** система возвращает `400 Bad Request`.

#### Scenario: Некорректный горизонт
- **WHEN** передан `horizon_days=0`
- **THEN** система возвращает `400 Bad Request`.
