# Tasks

Работа выполняется небольшими частями. После каждой завершённой части применяется Stop-and-Review из `AGENTS.md`; подтверждение одного коммита не распространяется на следующий.

## 1. Расчётный фундамент склада

- [x] 1.1 Реализовать чистый расчёт остатков партий и видов остатка на `as_of` по активным движениям и сохранённым распределениям. Проверка: тесты без HTTP и БД покрывают приход, расход, возврат, списание, корректировку и просрочку с точным `Decimal`.
- [x] 1.2 Реализовать выбор FEFO и проверку обеспеченности истории по дням с согласованным порядком внутри даты. Проверка: тесты покрывают несколько партий, равные сроки, поздний приход, нарушение на промежуточную дату и неизменность прежних распределений.
- [x] 1.3 Добавить вычисление `fefo_deviation` по актуальной истории для сохранённого расхода. Проверка: тесты фиксируют пустое предупреждение при обычном FEFO и предупреждение без перераспределения при позднем приходе.

## 2. Атомарная регистрация движений

- [x] 2.1 Реализовать репозиторий чтения истории и транзакционную блокировку `stock_locks` для пары товара и объекта. Проверка: интеграционный тест на PostgreSQL подтверждает, что два конкурентных расхода не могут оба списать общий недостаточный остаток.
- [x] 2.2 Реализовать сервис `receipt` и `consume`, запись партии и строк распределения, проверку прошлой даты и номера документа. Проверка: интеграционные тесты подтверждают пересчитанный остаток, FEFO, откат ошибочного расхода и `409` на дубль.
- [x] 2.3 Реализовать `writeoff`, `return` по исходной строке и положительную/отрицательную `correction` с причиной. Проверка: интеграционные тесты покрывают ограничение возврата, возврат просроченного, недостаток партии и неделимость штук.
- [x] 2.4 Реализовать атомарную связь `receipt` с подготовленным заказом поставщику. Проверка: тесты на PostgreSQL подтверждают частичную приёмку, отказ при превышении `pending_qty`, несовпадении товара/объекта/поставщика и отсутствие двойного учёта.

## 3. Складской HTTP API

- [x] 3.1 Добавить схемы запроса/ответа и `POST /api/movements` с машинными кодами и русскими сообщениями ошибок. Проверка: HTTP-тесты покрывают все типы движений, неизвестные ссылки, невалидный JSON, будущую дату, недопустимое количество, недостаток и дубликат документа.
- [x] 3.2 Добавить `GET /api/movements` с фильтрами, стабильной сортировкой, `total`, `limit`, `offset` и `warnings` у расходов. Проверка: HTTP-тесты проверяют границы пагинации, период, порядок и предупреждение после позднего прихода.
- [x] 3.3 Добавить `GET /api/stock` и `GET /api/stock/{sku}` с остатками на `as_of`, партиями, ценами и приходными документами. Проверка: HTTP-тесты подтверждают независимость объектов, просрочку, неизвестный SKU и `null` у показателей этапа 07.
