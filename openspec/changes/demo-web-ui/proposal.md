# Proposal

## Why

Backend и воспроизводимый демонабор доступны через сайт, но проверяющему без технической подготовки приходится самому искать сценарии, вводить SKU и параметры и сопоставлять действия с ответами сервера. Для проверки тестового задания по ссылке нужен короткий управляемый маршрут, в котором каждое действие показывает реальный HTTP-запрос, ответ и понятный результат.

## What Changes

- Добавить отдельный веб-сервис с русскоязычным интерфейсом для склада, предупреждений, прогноза, плана закупок и бюджета. Параметры пересчитываются через действующий API; рядом с числами доступны объяснения и ограничения.
- Добавить компактную форму проведения пяти типов движений и журнал с партиями и FEFO-распределением. Форма не отправляет операции для товаров `DEMO-`, сохраняя контрольный маршрут; API складских операций остаётся прежним.
- Оставить в интерфейсе место для AI-помощника со статусом «В разработке», без чата и авторизации.
- Включить создание полного демонабора при первом запуске на пустой БД на текущую дату Москвы. Повторный запуск сохраняет набор; новый читающий маршрут сообщает интерфейсу его контрольную дату.
- Запускать PostgreSQL, backend и веб-сервис одной командой `docker compose up`; добавить проверку сквозного маршрута и краткую техническую инструкцию. Клиентский `README.md` относится к этапу 13.
- Дополнить уже работающий сайт стартовым маршрутом «Проверить тестовое задание»: готовые действия для шести обязательных маршрутов API, FEFO и ошибок валидации с видимой цепочкой «действие → запрос → ответ → результат». Полный JSON доступен в раскрываемом блоке; ключевые поля объяснены обычным языком.
- Читающие сценарии использовать на защищённом `DEMO-` наборе. Записывающие сценарии выполнять через действующий `POST /api/movements` для `OIL-001`/`MS-01` с уникальными номерами документов в общей БД; повторные проверки накапливают операции, и интерфейс не обещает неизменный остаток для этой пары.

## Capabilities

### New Capabilities

- `web-ui`: отдельный веб-интерфейс сквозного сценария, заглушки AI и наглядной проверки обязательного backend через реальные запросы и ответы.

### Modified Capabilities

- `app-foundation`: единый запуск Compose включает веб-сервис и проверку его готовности.
- `demo-data`: первый запуск создаёт набор автоматически; читающий HTTP-маршрут сообщает контрольную дату без изменения существующей CLI-команды.

## Impact

Существующие статические ресурсы сайта, HTTP-клиент, сквозной тест веб-прокси и `doc/ui-demo.md`; новые небольшие JS-модули и техническая инструкция проверки. Контракты backend API, схема БД, демонабор и логика расчётов не меняются. Клиентский `README.md` остаётся задачей этапа 13.
