# Spec Delta

## ADDED Requirements

### Requirement: Автоматическая подготовка демонабора для сайта
После миграций и обычных начальных сидов система SHALL при отсутствии записей демонабора однократно создавать полный набор `DEMO-` с `as_of`, равной текущей дате `Europe/Moscow`. При повторном запуске существующий набор SHALL сохраняться без автоматической пересборки на новую дату. Если имеются лишь некоторые ключи набора, запуск SHALL завершаться ошибкой подготовки вместо молчаливого дополнения или удаления. Существующая CLI-команда с обязательной явной датой и режимом `--replace` SHALL сохранять своё поведение.

#### Scenario: Чистая БД
- **WHEN** приложение впервые запускается без ключей `DEMO-`
- **THEN** полный набор создаётся на текущую дату Москвы до готовности API.

#### Scenario: Перезапуск через день
- **WHEN** набор создан вчера и приложение перезапущено сегодня
- **THEN** контрольная дата и записи набора сохраняются, новых движений и заказов не возникает.

#### Scenario: Неполный набор
- **WHEN** часть ожидаемых ключей `DEMO-` присутствует, а часть отсутствует
- **THEN** backend отказывает в запуске с понятной причиной и не меняет БД.

### Requirement: Читающий статус демонабора
`GET /api/demo/status` SHALL возвращать `200` с JSON `{"ready": true, "as_of": "YYYY-MM-DD"}` для подготовленного набора; дата SHALL соответствовать фактической контрольной дате записей. Если набор отсутствует или структурно неполон, маршрут SHALL возвращать `503` без секретов и без изменения данных.

#### Scenario: Сайт узнаёт дату
- **WHEN** набор подготовлен на дату `2026-09-29`
- **THEN** `GET /api/demo/status` возвращает `ready: true` и `as_of: "2026-09-29"`.

#### Scenario: Набор недоступен
- **WHEN** данные отсутствуют или часть ожидаемых ключей повреждена
- **THEN** `GET /api/demo/status` возвращает `503`, не создавая и не восстанавливая записи.
