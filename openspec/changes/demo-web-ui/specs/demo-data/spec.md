# Spec Delta

## ADDED Requirements

### Requirement: Автоматическая подготовка демонабора для сайта
После миграций каждый запуск приложения в Compose SHALL транзакционно очищать предметные таблицы, сохраняя ревизию Alembic. Затем система SHALL заново загружать обычные сиды и полный набор `DEMO-` с `as_of`, равной текущей дате `Europe/Moscow`. Записи и движения посетителей SHALL существовать до следующего запуска приложения и удаляться при нём. Существующая CLI-команда с явной датой и режимом `--replace` SHALL сохранять поведение вне запуска Compose.

#### Scenario: Чистая БД
- **WHEN** приложение впервые запускается без ключей `DEMO-`
- **THEN** полный набор создаётся на текущую дату Москвы до готовности API.

#### Scenario: Перезапуск через день
- **WHEN** набор создан вчера, посетители провели движения и приложение перезапущено сегодня на том же томе
- **THEN** изменения посетителей удалены, исходные данные восстановлены на сегодняшнюю дату Москвы и дублирования нет.

#### Scenario: Повреждённый набор на томе
- **WHEN** часть ожидаемых ключей `DEMO-` отсутствует перед запуском Compose
- **THEN** запуск очищает предметные таблицы и восстанавливает полный набор.

### Requirement: Читающий статус демонабора
`GET /api/demo/status` SHALL возвращать `200` с JSON `{"ready": true, "as_of": "YYYY-MM-DD"}` для подготовленного набора; дата SHALL соответствовать фактической контрольной дате записей. Если набор отсутствует или структурно неполон, маршрут SHALL возвращать `503` без секретов и без изменения данных.
Дополнительные движения и партии посетителей SHALL не делать статус недоступным при наличии обязательных ключей.

#### Scenario: Сайт узнаёт дату
- **WHEN** набор подготовлен на дату `2026-09-29`
- **THEN** `GET /api/demo/status` возвращает `ready: true` и `as_of: "2026-09-29"`.

#### Scenario: Набор недоступен
- **WHEN** данные отсутствуют или часть ожидаемых ключей повреждена
- **THEN** `GET /api/demo/status` возвращает `503`, не создавая и не восстанавливая записи.
