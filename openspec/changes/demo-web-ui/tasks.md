- [ ] 1.1 Создать `app/demo_data/bootstrap.py`: при отсутствии любых `DEMO-` ключей вызвать `prepare_demo_data()` с `today_in_moscow()`, при существующем наборе проверить ключи и опорную дату без записи, при частичном наборе завершить запуск с ошибкой без секретов. В `tests/test_demo_bootstrap.py` проверить создание на фиксированную дату `2026-09-29`, повтор при дате `2026-09-30` без изменения набора, сохранение посторонней записи и отказ при недостающем ключе.

- [ ] 2.1 Изменить `docker-compose.yml`: после сидов выполнять `python -m app.demo_data.bootstrap`, добавить healthcheck `app`, сервис `web` с ожиданием готового backend и портом `WEB_PORT`; внести `WEB_PORT=8080` в `.env.example`. Обновить `tests/test_compose_lifecycle.py` и `scripts/test_compose_lifecycle.sh`: проверить наличие девяти `DEMO-` SKU, прежнюю дату после перезапуска и сохранение пользовательской записи вместо старого точного счёта только сидов. Проверка — оба сквозных сценария Compose на изолированных томах проходят.
- [ ] 2.2 Создать `web/Dockerfile`, `web/nginx.conf` и начальный `web/index.html`: отдельный Nginx отдаёт HTML, проксирует `/api/`, `/docs`, `/openapi.json`, `/health` в `app`. Создать `scripts/test_web_ui_e2e.sh` для изолированного Compose-проекта: проверить ответ страницы, прокси `/api/demo/status`, `/api/stock`, `/api/alerts` и `POST /api/procurement/plan`; подключить сценарий в `scripts/check.sh`. Проверка — сквозной сценарий получает `200` и реальные поля ответов через порт сайта, а при сбое bootstrap сайт не выдаёт успешные расчёты.
