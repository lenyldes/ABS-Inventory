# Предложение: дорожная карта проекта

## Why

В репозитории есть исходное тестовое задание и бизнес-требования, но нет общего плана реализации. Нужна дорожная карта, которая связывает обязательный backend и согласованный демонстрационный прототип, позволяя двигаться небольшими изменениями через OpenSpec.

## What Changes

- Создать `doc/ROADMAP.md` на русском языке с этапами, результатами, зависимостями и критериями завершения.
- Разделить требования тестового задания, согласованные расширения демонстрации и отложенные возможности полного продукта.
- Зафиксировать целевой сценарий: склад → риски → прогноз → план закупок → бюджет, доступный через интерфейс и AI-чат на русском языке.
- Отметить обязательный стек, предложенные архитектурные решения и вопросы, требующие отдельного обсуждения.
- Описать переход от крупных этапов к небольшим изменениям OpenSpec; тестирование и документация сопровождают каждый этап.

## Capabilities

### New Capabilities

Нет. Изменение касается только планирования в документации и не добавляет поведения приложения. В метаданных изменения используется `skip_specs: true`.

### Modified Capabilities

Нет.

## Impact

При применении изменяется только `doc/ROADMAP.md`. Исходники в `doc/SOW` сохраняются без изменений. Перенос PDF, создание `AGENTS.md`, реализация приложения, AI-интеграция и развёртывание обозначаются будущими этапами; в это изменение они не входят.

Срок «3 дня» остаётся фактом исходного задания, но по решению пользователя не ограничивает план: приоритет — качество. Пользователь предоставит API для подключения модели; выбор провайдера и интерфейсного стека пока открыт. Код, зависимости, настройки OpenSpec и инфраструктура не меняются.
