# delivery Specification

## Purpose
Определяет требования к содержанию, структуре и полноте итоговой документации проекта в README.md, включая архитектурное описание, запуск, тестирование, конфигурацию, презентацию демонстрационного стенда, методологию разработки с ИИ и мотивацию автора.

## Requirements

### Requirement: README Document Structure and Constraints
Корень репозитория ДОЛЖЕН (SHALL) содержать файл `README.md`, оформленный в формате GitHub Flavored Markdown, размер которого строго НЕ ПРЕВЫШАЕТ (MUST NOT exceed) 10 000 символов в кодировке UTF-8 согласно стандартам `AGENTS.md`. Документ ДОЛЖЕН (SHALL) содержать заголовок, навигационные бейджи, ссылки на живой стенд, спецификацию OpenAPI и Swagger UI.

#### Scenario: Проверка наличия и размера README
- **WHEN** выполняется скрипт проверки качества проекта `bash scripts/check.sh`
- **THEN** файл `README.md` существует в корне репозитория и его длина не превышает 10 000 символов

### Requirement: System Architecture and Stock Calculation Documentation
Документ `README.md` ДОЛЖЕН (SHALL) содержать наглядное описание модульной архитектуры приложения с разделением слоёв (транспорт API, репозитории доступа к данным, чистые функциональные модули расчётов без HTTP и БД) и детальное описание алгоритма вычисления остатка из движений и партий без денормализованного поля.

#### Scenario: Проверка описания архитектуры и расчёта остатка
- **WHEN** технический эксперт изучает раздел «Архитектура решения» в `README.md`
- **THEN** он видит чёткое разграничение ответственности между слоями и математически строгий принцип расчёта остатка по формуле приходов и расходов с учётом даты актуальности `as_of` и правил FEFO

### Requirement: Deployment, Test, and Configuration Instructions
Документ `README.md` ДОЛЖЕН (SHALL) содержать однозначные инструкции по локальному развёртыванию стека сервисов одной командой через Docker Compose, инструкции по тестированию через `pytest` и `scripts/check.sh`, а также структурированную таблицу всех переменных окружения из `.env.example` с их назначением и значениями по умолчанию.

#### Scenario: Развёртывание и тестирование по инструкциям из README
- **WHEN** разработчик следует инструкциям из разделов «Быстрый старт» и «Тестирование» в `README.md`
- **THEN** приложение успешно поднимается через `docker compose up --build`, а все тесты проходят через `docker compose run --rm test pytest`

### Requirement: Live Stand and Demonstration Scenarios
Документ `README.md` ДОЛЖЕН (SHALL) презентовать публичный демонстрационный стенд по адресу `https://abs-inventory.lenyldes.ru`, описывать интерактивный стенд проверки обязательных API («01 · Проверка API») без необходимости ручного ввода параметров, сквозной сценарий («02 · Сквозной маршрут») и механизм сброса к контрольной дате `2026-09-29`.

#### Scenario: Использование демонстрационного стенда
- **WHEN** проверяющий открывает ссылку стенда из `README.md`
- **THEN** он получает доступ к защищённому HTTPS-интерфейсу, интерактивной проверке контрактов ТЗ в один клик и актуальной документации Swagger UI

### Requirement: AI Collaboration and Author Motivation Block
Документ `README.md` ДОЛЖЕН (SHALL) описывать инженерную культуру разработки в паре с ИИ (AI-assisted engineering, OpenSpec, TDD, лимиты, Stop-and-Review), а также содержать развёрнутые ответы автора на вопросы ТЗ о мотивации участия, роли в команде и доступном времени.

#### Scenario: Ознакомление с процессом разработки и мотивацией
- **WHEN** нанимающий менеджер читает разделы о процессе разработки и мотивации в `README.md`
- **THEN** он видит подтверждённые факты совместной разработки с ИИ (108 коммитов, 355+ тестов, 12 спецификаций) и персональные ответы автора на вопросы тестового задания
